Project Architecture

DocuChat AI is a monorepo with two completely independent apps that share a single GitHub repository. Each app has its own package.json, node_modules, and runtime environment.

frontend/
React + Vite SPA
The user interface. Built with React 18 and Vite. Communicates with the backend only via HTTP. Has no direct database access.
backend/
Express.js REST API
All business logic lives here — file ingestion, vector search, LLM calls, auth, and chat history persistence.
MongoDB (local / Atlas)
Persistent Storage
Stores users, chat history. Currently the vector index is stored on the local filesystem (not MongoDB) — see ingest.js.
Cloudinary
File Storage CDN
Every uploaded PDF/image is uploaded to Cloudinary immediately after receipt. The raw file buffer is never written to disk on the server.

uploadToCloudinary() helper

Accepts a raw Buffer and original filename. Uses the Cloudinary upload stream API to avoid buffering the entire file twice. Returns { url, publicId } on success.

function uploadToCloudinary(buffer, filename) {
  return new Promise((resolve, reject) => {
    // Sanitise filename → safe publicId
    const publicId = `pdf-qa-bot/${safeName}-${Date.now()}`;
    const stream = cloudinary.uploader.upload_stream(
      { resource_type: "auto", public_id: publicId },
      (error, result) => { if (error) reject(...); else resolve({url, publicId}); }
    );
    stream.end(buffer); // push buffer into the upload stream
  });
}

splitQuestions() — Multi-question detection

Before calling runQA, the server splits the user's question string on ?. If the user asks "What is X? What is Y?", it runs two parallel Q&A calls and returns both results in the results[] array.

ingestText() — Core function (called by all handlers)

async function ingestText(text, filename, fileSize, extraMeta, cloudinaryData, userId) {
  // 1. Split text into ~1000-char chunks with 150-char overlap
  const splitter = new RecursiveCharacterTextSplitter({ chunkSize: 1000, chunkOverlap: 150 });
  const docs = await splitter.createDocuments([text], [{ source: filename }]);

  // 2. Embed all chunks with text-embedding-ada-002 via OpenRouter
  const embeddings = new OpenAIEmbeddings({ model: "openai/text-embedding-ada-002", ... });
  const newStore = await MemoryVectorStore.fromDocuments(docs, embeddings);

  // 3. Generate a 2-3 sentence summary of the document
  const summary = await generateSummary(text);

  // 4. Read existing store.json, merge new vectors with old, save
  const mergedVectors = [...existingVectors, ...newStore.memoryVectors];
  fs.writeFileSync(indexFile, JSON.stringify({ vectors, files, cloudinaryMeta }));
}

Vector Index Storage Format

Each user gets their own directory: ./vector_index/{userId}/store.json. The JSON file has this shape:

{
  "vectors": [
    {
      "content": "...chunk text...",
      "embedding": [0.023, -0.417, 0.891, ...],   // 1536 floats
      "metadata": { "source": "report.pdf", "totalPages": 12 }
    },
    ...
  ],
  "files": [
    { "name": "report.pdf", "size": 204800, "uploadedAt": "2026-04-04T...", "summary": "..." }
  ],
  "cloudinaryMeta": {
    "report.pdf": { "url": "https://res.cloudinary.com/...", "publicId": "pdf-qa-bot/..." }
  }
}
Vercel Incompatibility The fs.writeFileSync / fs.readFileSync calls here write to the local filesystem. Vercel serverless functions have a read-only filesystem. This must be replaced with MongoDB reads/writes before deploying to Vercel.

Backend — qa_chain.js

backend/qa_chain.js

Role: Loads the vector index, retrieves relevant document chunks for a question, builds a prompt, and calls the LLM. Exposes both a regular (non-streaming) and a streaming (async generator) version.

Two-Level Cache

CacheKeyValueWhy
vectorStoreCache (Map)userId{ store, embeddings }Avoids re-reading and re-parsing store.json from disk on every request. Cleared by invalidateCache(userId) after any new ingest or delete.

Multi-Model Support via TIKTOKEN_MAP

LangChain's ChatOpenAI uses tiktoken internally to count tokens. tiktoken only knows bare OpenAI model names. But OpenRouter requires prefixed names like "openai/gpt-4o-mini". The fix:

const TIKTOKEN_MAP = {
  "openai/gpt-4o-mini":          "gpt-4o-mini",   // exact match
  "anthropic/claude-3.5-sonnet": "gpt-4o",        // approximation
  "google/gemini-2.5-flash":     "gpt-4o",        // approximation
};
// createLLM() maps the model name for tiktoken, but passes the real
// model name in modelKwargs so OpenRouter receives the correct model.

Retrieval Pipeline — retrieveChunks()

Standard mode (no query expansion): embeds the question, calls similaritySearchVectorWithScore() with an optional file filter, then filters results below a 0.2 cosine similarity threshold.

Query expansion mode: generates 2 alternative phrasings of the question via the LLM, retrieves top-k chunks for each phrasing, deduplicates by content prefix, then re-ranks by score and returns the best k.

runQA() — Non-Streaming

Runs all 4 pipeline steps synchronously. Returns a single JSON object with { answer, sources, trace, suggestions }. Used by POST /api/ask.

runQAStream() — Async Generator (Streaming)

An async function* (async generator). The Express handler reads from this generator and writes each event to the SSE response. Yields three event types:

Event typePayloadWhen
token{ type:"token", content:"..." }For every chunk streamed from the LLM
done{ type:"done", answer, sources, trace, suggestions }After stream completes and suggestions/sources are built
error{ type:"error", message:"..." }If any step fails
Trace System Both runQA and runQAStream maintain a trace[] array that records each pipeline step with { title, detail, state }. The frontend's ExecutionTrace.jsx renders this as a step-by-step execution log so users can see exactly what happened.

Backend — Auth System

routes/auth.js

backend/routes/auth.js

Three routes. No external auth service — everything is done with bcryptjs and jsonwebtoken.

RouteInputLogicResponse
POST /registername, email, passwordCheck email not taken → bcrypt.hash(password, 12) → User.create() → jwt.sign(){ token, user }
POST /loginemail, passwordUser.findOne(email) → bcrypt.compare() → jwt.sign(){ token, user }
GET /meAuthorization headerrequireAuth middleware validates JWT → return req.user{ user }

JWT Token

Signed with process.env.JWT_SECRET. Expires in 7 days. Payload: { id, name, email }. Verified on every protected route by authMiddleware.js.

middleware/authMiddleware.js

backend/middleware/authMiddleware.js
export function requireAuth(req, res, next) {
  const token = req.headers.authorization?.slice(7); // strip "Bearer "
  if (!token) return res.status(401).json({ error: "Authentication required." });
  const decoded = jwt.verify(token, process.env.JWT_SECRET);
  req.user = { id: decoded.id, name: decoded.name, email: decoded.email };
  next(); // attaches user to the request for all downstream handlers
}

Every downstream route accesses the authenticated user via req.user.id. All vector index operations are namespaced by userId — users can never access each other's data.

Key Handlers

handleUpload(files, onProgress)

Creates a FormData with all selected files. If onProgress callback is provided, uses XMLHttpRequest (which exposes upload progress events). Otherwise falls back to authFetch. On success, updates indexed and indexedFiles.

streamAsk(question, baseMessages, onToken, onDone, onError)

Calls POST /api/ask/stream. Reads the SSE response body using the browser's ReadableStream API. Buffers partial lines and dispatches events:

const reader = res.body.getReader()
const decoder = new TextDecoder()
let buffer = ''
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  buffer += decoder.decode(value, { stream: true })
  const lines = buffer.split('\n'); buffer = lines.pop()
  for (const line of lines) {
    if (!line.startsWith('data: ')) continue
    const event = JSON.parse(line.slice(6))
    if (event.type === 'token') onToken(event.content)
    else if (event.type === 'done') { onDone(event); return }
  }
}

handleAsk(question)

Immediately adds a user message and a blank streaming assistant message to the state (optimistic UI). Calls streamAsk(). On each token, appends to the streaming message in place. On done, replaces the streaming message with the final message (including sources, trace, suggestions).

handleRegenerate(question)

Finds and removes the last assistant message from state, then re-runs streamAsk() for the same question. Uses PUT /api/chat/history (replace all) to sync the final state to MongoDB.

handleExportChat()

Converts the messages array to Markdown, creates a Blob, creates a temporary anchor element, and triggers a download. No server round-trip — entirely client-side.

Frontend — Chat.jsx

frontend/src/components/Chat.jsx

Role: The main panel. Renders the message list, the input bar, drag-and-drop upload, and the file scope filter. Contains all scroll and edit logic.

Scroll Management

Uses two useRefs: messagesBoxRef (the scrollable container) and messagesEndRef (a sentinel div at the bottom). The scrollToBottom(force) function uses a 30ms debounce timeout — it skips the scroll if the user is scrolled more than 120px from the bottom (so reading history isn't interrupted), unless force=true (new user message).

Inline Message Edit

Clicking "Edit" on a user message sets editingIndex and replaces the bubble with an inline textarea. On submit, it calls onTrimMessages(index) (removes everything from that index onward in both state and MongoDB), then fires a new onAsk() with the edited content — creating a fresh branch of conversation.

validateAndUpload()

Checks file extension against the accepted list. Enforces the 5-document limit by comparing indexedFiles.length before calling onUpload(). Shows inline error text for invalid files.

When more than one file is indexed, a <select> appears above the input bar. Choosing a specific file sets filterFile in App.jsx state, which is passed as a query parameter to /api/ask/stream. The backend uses it to filter the vector similarity search to only chunks from that file.

Complete API Reference

POST /api/auth/register

Body: { name, email, password }  |  Response: { token, user: { id, name, email } }

Validates that password ≥ 6 chars. Hashes password with bcrypt cost 12. Returns 409 if email already exists.

POST /api/auth/login

Body: { email, password }  |  Response: { token, user }

Returns 401 with a generic error message for both wrong email and wrong password (prevents user enumeration).

POST /api/upload

Content-Type: multipart/form-data, field name: file (supports multiple)  |  Max file size: 50 MB

Response: { success, message, chunks, files }

Enforces a 5-document limit per user. Uploads each file to Cloudinary, then runs ingestFile(). Returns updated files[].

POST /api/ask

Body:

{
  question: "What is X?",
  k: 4,                          // number of chunks to retrieve
  chainType: "stuff",             // "stuff" is the only supported type
  model: "openai/gpt-4o-mini",   // any OpenRouter model ID
  filterFile: "report.pdf",       // optional: scope to one file
  queryExpansion: false,           // optional: generate query variants
  history: [{ role, content }]      // last N messages for context
}

Response: { results: [{ question, answer, sources, trace, suggestions }] }

POST /api/ask/stream

Same body as /api/ask. Response: Content-Type: text/event-stream

SSE events format: data: {"type":"token","content":"..."}\n\n

Sequence: N × token events → 1 × done event (with full answer + sources + trace + suggestions)

DELETE /api/index/:filename

URL-encodes the filename. Filters vectors and files from store.json. Calls cloudinary.uploader.destroy() for the file. If no files remain, deletes the entire user index directory.

DELETE /api/index

Destroys all Cloudinary files for the user (reads cloudinaryMeta from store.json), then deletes the entire ./vector_index/{userId}/ directory.

Data & Request Flow

Upload Flow

User selects file in browser
  → FormData sent via XHR to POST /api/upload (with progress events)
  → multer stores file as Buffer in memory (req.files[])
  → uploadToCloudinary(buffer, name) → Cloudinary CDN → returns {url, publicId}
  → ingestFile(buffer, name, cloudinaryData, userId)
      → extract text (pdf-parse / xlsx / vision LLM)
      → chunk into 1000-char pieces with 150 overlap
      → embed all chunks with text-embedding-ada-002
      → generate 2-3 sentence summary
      → read existing store.json (if exists) → merge vectors + files
      → write updated store.json to ./vector_index/{userId}/
  → invalidateCache(userId) clears vectorStoreCache
  → respond { success, files[] }

Q&A Streaming Flow

User types question → presses Enter
  → App.jsx handleAsk() adds { role:'user', content } to messages
  → adds { role:'assistant', content:'', streaming:true } placeholder
  → POST /api/ask/stream

Backend:
  → requireAuth validates JWT, sets req.user.id
  → runQAStream* generator starts
  → getVectorStore(uid): check cache → if miss, read store.json, hydrate MemoryVectorStore
  → getEmbedding(question): check cache → if miss, call embedding API
  → similaritySearchVectorWithScore(queryEmbedding, k, filterFile?)
  → filter results below 0.2 cosine threshold
  → build prompt with context + conversation history
  → chain.stream(question) → yields LangChain tokens
  → for each token: yield { type:'token', content }  ← sent as SSE line
  → after stream: generate suggestions (separate LLM call)
  → yield { type:'done', answer, sources, trace, suggestions }

Browser SSE reader:
  → each 'token' event: append content to streaming message
  → 'done' event: replace streaming message with final message
  → appendHistory([userMsg, assistantMsg]) → POST /api/chat/history

Auth Flow

Page load:
  → AuthContext reads localStorage('pdfbot_token')
  → if token exists: GET /api/auth/me → sets user state
  → if no token or invalid: show Login page

Login:
  → POST /api/auth/login → receives { token, user }
  → stores token in localStorage + sets user state
  → App.jsx renders MainApp

Logout:
  → removes localStorage token → sets user/token to null
  → App.jsx renders Login

Key Algorithms Explained

Vector Similarity Search (Cosine Similarity)

When a user asks a question, it is converted into a 1536-dimensional float vector (embedding). The system compares this vector against every stored chunk vector using cosine similarity — a score between 0 and 1. A score of 1.0 means the vectors point in exactly the same direction (semantically identical). The top-k most similar chunks are returned as context.

A minimum threshold of 0.2 filters out completely unrelated chunks. If no chunk passes the threshold, the best single result is returned anyway (fallback — prevents empty context).

Recursive Text Splitting

LangChain's RecursiveCharacterTextSplitter splits on \n\n, then \n, then " " — trying to keep semantically complete units (paragraphs, sentences) together. Parameters used: chunkSize=1000 chars, chunkOverlap=150 chars. The overlap ensures context at chunk boundaries isn't lost.

Query Expansion

When enabled, a lightweight LLM call generates 2 alternative phrasings of the user's question. This improves recall for questions that use different vocabulary than the source document. The three queries (original + 2 alternatives) are each embedded and searched independently. Results are merged, deduplicated by content (first 120 chars used as key), re-ranked by score, and truncated to top-k.

Streaming with Server-Sent Events (SSE)

The server sets Content-Type: text/event-stream and keeps the HTTP connection open. As the LLM generates tokens, each is written as data: {...}\n\n. The browser reads this using the ReadableStream API — not EventSource (which doesn't support POST). This allows the app to stream into an existing POST request while passing the full auth token and body payload.

Image Understanding via Vision LLM

For uploaded images, the system Base64-encodes the image and sends it to GPT-4o-mini's vision endpoint with a detailed prompt asking for a comprehensive description. This description is then embedded and stored like any other text chunk. The result: users can ask questions about diagrams, charts, flowcharts, or scanned documents just like they ask about PDFs.

LRU Embedding Cache

The embeddingCache Map holds up to 100 question → embedding pairs. When the 101st entry is added, the oldest entry (first key in insertion order) is evicted. This is a simple manual LRU using JavaScript Map's guaranteed insertion-order iteration. It prevents repeat embedding API calls for identical questions in the same server session.

Settings Persistence The settings object (k, model, queryExpansion, etc.) is saved to localStorage under the key pdfbot_settings on every change. It also includes a model migration guard — if the stored model is an old Gemini ID, it is automatically upgraded to the current ID on load.
