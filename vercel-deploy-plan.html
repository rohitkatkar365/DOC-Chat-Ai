1 Architecture Overview

Your project is a monorepo with two separate apps. Here is how they map to Vercel's deployment model:

Frontend (React + Vite)

Deployed as a Vercel Static Site. Vite builds it into dist/, served from Vercel's global CDN. Zero server required.

Backend (Express.js)

Deployed as a Vercel Serverless Function using @vercel/node. Your entire Express app runs as one serverless endpoint.

Database

Replaced local MongoDB with MongoDB Atlas (free M0 tier). All user data, chat history, and the vector index live here.

File Storage

Already using Cloudinary — no change needed. Uploaded PDFs/images are stored there.

Important Constraint Vercel's serverless functions have a read-only filesystem. Your backend currently writes the vector index to ./vector_index/ on disk. This will NOT work on Vercel. Step 3 covers how to fix this by storing the index in MongoDB instead.

3 Critical Code Change — Move Vector Index to MongoDB

Required Before Deploying This is the most important change. Without it your uploads and Q&A will silently break on Vercel because the ./vector_index/ directory cannot persist between serverless function invocations.

3.1 — Create a Mongoose model for the vector store

Create a new file backend/models/VectorIndex.js:

backend/models/VectorIndex.js
import mongoose from "mongoose";

const vectorIndexSchema = new mongoose.Schema({
  userId: { type: String, required: true, unique: true },
  vectors: { type: Array, default: [] },
  files:   { type: Array, default: [] },
  cloudinaryMeta: { type: Object, default: {} },
}, { timestamps: true });

export const VectorIndex = mongoose.model("VectorIndex", vectorIndexSchema);

3.2 — Replace filesystem reads/writes in ingest.js

Wherever ingest.js reads or writes store.json, replace with MongoDB calls:

Pattern to replace in ingest.js
// BEFORE (filesystem — does not work on Vercel)
import fs from "fs";
const indexFile = path.join("./vector_index", uid, "store.json");
fs.writeFileSync(indexFile, JSON.stringify(data));
const data = JSON.parse(fs.readFileSync(indexFile, "utf8"));

// AFTER (MongoDB — works everywhere)
import { VectorIndex } from "./models/VectorIndex.js";
await VectorIndex.findOneAndUpdate(
  { userId: uid },
  { $set: { vectors, files, cloudinaryMeta } },
  { upsert: true }
);
const doc = await VectorIndex.findOne({ userId: uid });
Also update server.js The DELETE /api/index and DELETE /api/index/:filename routes in server.js also use fs.readFileSync / fs.rmSync on the vector_index folder. Update those routes to use VectorIndex.findOneAndDelete() / VectorIndex.findOneAndUpdate() instead.

4 Add Vercel Configuration Files

Create a vercel.json at the root of your project. This tells Vercel how to build and route both apps from one repository.

vercel.json (project root)
{
  "version": 2,
  "builds": [
    {
      // Backend: wrap Express as a serverless function
      "src": "backend/server.js",
      "use": "@vercel/node"
    },
    {
      // Frontend: build with Vite
      "src": "frontend/package.json",
      "use": "@vercel/static-build",
      "config": { "distDir": "dist" }
    }
  ],
  "routes": [
    {
      // API calls go to the Express serverless function
      "src": "/api/(.*)",
      "dest": "backend/server.js"
    },
    {
      // Everything else serves the React SPA
      "src": "/(.*)",
      "dest": "frontend/$1"
    }
  ]
}
Frontend build command Vercel needs a build script in frontend/package.json. You already have "build": "node node_modules/vite/bin/vite.js build" — that's fine. Vercel will run it automatically.

6 Set Up MongoDB Atlas

  • 1
    Create a free cluster

    Log in to cloud.mongodb.com → Create a cluster → choose M0 Free Tier → select any region → click Create Cluster.

  • 2
    Create a database user

    Go to Security → Database Access → Add New Database User. Set authentication to Password. Save the username and password — you'll need them for the connection string.

  • 3
    Whitelist all IPs (for Vercel)

    Go to Security → Network Access → Add IP Address → click "Allow Access from Anywhere" (0.0.0.0/0). Vercel uses dynamic IPs so this is required.

  • 4
    Get your connection string

    Go to Clusters → Connect → Connect your application. Copy the URI. It will look like:

    mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/pdfqabot?retryWrites=true&w=majority

    Replace <username> and <password> with your database user credentials.

8 Configure Environment Variables

In the Vercel project → Settings → Environment Variables, add all of the following:

Variable Name Value Notes
MONGODB_URI Your Atlas connection string From Step 6.4 — include database name
JWT_SECRET A long random string Generate with: openssl rand -hex 32
OPENROUTER_API_KEY Your OpenRouter key From your current .env
OPENROUTER_BASE_URL https://openrouter.ai/api/v1 Same as local
CLOUDINARY_CLOUD_NAME dr2qvcj91 From your current .env
CLOUDINARY_API_KEY Your Cloudinary API key From your current .env
CLOUDINARY_API_SECRET Your Cloudinary secret From your current .env
ALLOWED_ORIGINS Your Vercel frontend URL e.g. https://docuchat-ai.vercel.app — set AFTER first deploy
NODE_ENV production Enables production error handling
Two-step for ALLOWED_ORIGINS You won't know your Vercel URL until after the first deploy. For the first deploy, set ALLOWED_ORIGINS=* temporarily, then update it to your real URL after deployment.
Apply to all environments When adding each variable in Vercel, check all three boxes: Production, Preview, and Development.

9 Configure Frontend API URL

Your frontend must call the backend at the right URL. The cleanest approach is to use a Vite environment variable.

9.1 — Create environment files

frontend/.env.development (local dev)
VITE_API_URL=http://localhost:3001
frontend/.env.production (Vercel build)
# Leave empty — on Vercel, frontend and backend share the same domain
VITE_API_URL=

9.2 — Use the variable in your fetch calls

Find every place in your React code that hardcodes the API URL (e.g. http://localhost:3001/api/...) and replace it:

frontend/src — any file with API calls
// Before
fetch("http://localhost:3001/api/upload", ...)

// After
const BASE = import.meta.env.VITE_API_URL || "";
fetch(`${BASE}/api/upload`, ...)

When VITE_API_URL is empty (on Vercel), the path resolves to /api/upload — a relative URL that hits the same Vercel domain where the serverless backend runs.

10 Deploy & Verify

  • 1
    Trigger the first deployment

    In the Vercel dashboard, click "Deploy". Vercel will clone your repo, run both builds, and publish. This takes ~2–3 minutes. Watch the build logs for errors.

  • 2
    Check build logs

    In the deployment log, confirm you see:

    • Frontend: vite build completes without errors
    • Backend: @vercel/node bundles server.js without errors
  • 3
    Test the backend health endpoint

    Visit https://your-app.vercel.app/api/auth/... (or any public endpoint) in your browser. You should get a JSON response, not a 404.

  • 4
    Update ALLOWED_ORIGINS

    Copy your Vercel URL (e.g. https://docuchat-ai.vercel.app). Go to Vercel → Settings → Environment Variables → update ALLOWED_ORIGINS to that URL. Then trigger a new deployment (push an empty commit or click Redeploy).

  • 5
    End-to-end test
    • Register a new account
    • Upload a PDF file
    • Ask a question — confirm a streaming answer appears
    • Delete the document — confirm it is removed

11 Post-Deployment Checklist

  • Vector index reads/writes use MongoDB (not local filesystem)
  • MONGODB_URI points to Atlas (not localhost)
  • ALLOWED_ORIGINS is set to the live Vercel URL
  • .env files are in .gitignore and never committed
  • Frontend uses VITE_API_URL (empty string = relative URL) for all API calls
  • vercel.json is committed to the root of the repository
  • MongoDB Atlas Network Access allows 0.0.0.0/0
  • Cloudinary credentials are set in Vercel env vars (not hardcoded)
  • JWT_SECRET is a new, strong random value (not the development placeholder)
  • End-to-end flow tested: register → upload → ask → delete
Continuous Deployment Once set up, every git push to your main branch automatically triggers a new Vercel deployment. Preview deployments are created for every pull request automatically.
